# 과금 구조 설계 — 리뷰 기반 단계적 유료화

## 0. 지금의 안 (고민 리포트 + 신년운세) — 아래 1~6절보다 우선

처음 설계(아래)는 ‘풀이 리포트의 섹션을 잠그는’ 방식이었다. 지금은 **무료는 진단(나는 어떤 사람인지), 유료는 처방(언제·어떻게)** 으로 나눈다.

| 구분 | 내용 |
| --- | --- |
| 무료 | 만세력·원국, 결론, 맞혀 볼게요, 풀이 리포트(종합·성향·연애 스타일·일 스타일·돈 그릇·건강 체질), 운의 흐름(이번 달·다음 달·연도별 한 줄·대운), 교차 검증, MBTI, 인생 웹툰, 전문 분석. 고민마다 한 줄 답·이유·올해와 내년 신호·개운법 한 가지. 신년운세는 그해 한 줄·이유·띠와 삼재·힘이 가장 실리는 달 하나 |
| 유료 | 고민 상세: 앞으로 12개월 좋은 달·피할 달, 10년 신호와 때를 읽는 풀이, 지금 할 일, 고민별 개운법 / 신년운세 상세: 열두 달, 기회의 달·조심할 달, 분야별, 그해 개운법, 대운 속 위치 / 궁합·재회 상세 |
| 가격 | 고민 하나 **3,900원** · 신년운세 **6,900원**(해마다) · 전부 열기 **9,900원**(고민 4개 + 그해 신년운세, 하나씩 산 금액은 빼 줌) · 궁합·재회 상대 1명 **4,900원** |
| 첫 결제 혜택 | 한 번도 결제하지 않은 계정은 고민 4개 중 하나를 **처음 한 번만 1,900원**에 연다(신년운세·궁합은 정가). 낸 돈은 전부 열기 차액에 그대로 셈한다. 하나를 사고 나서 전부 열기까지 1,000원도 안 남으면 하나 대신 ‘나머지 전부’만 보여 준다(몇백 원짜리 결제를 만들지 않으려고) |
| 잠금 화면 | 무엇이 들어 있는지 목록 + **내 사주로 이미 계산된 결과 하나를 먼저 보여 준다**: 고민은 좋은 달 중 첫 달, 신년운세는 조심할 달 중 첫 달(힘이 실리는 달은 무료에 이미 있어서), 궁합은 앞으로 10년 중 한 해, 재회는 연락하기 좋은 달 중 첫 달 |
| 측정 | 접속 → 결과 봄 → 고민 리포트 펼침 → 상세나 가격 화면까지 봄 → 결제 버튼 → 결제 완료를 이름·생년월일 없이 센다(`src/lib/funnel.ts`). 관리 화면 맨 위 ‘결제까지 가는 길’에서 단계마다 남은 사람, 고민별 표, 접속한 사람 1명당 매출을 본다 |
| 시즌 | 10월부터 다음 해 입춘 전까지 ‘올해 운세’ 칸이 다음 해 신년운세가 되어 맨 앞에 선다(`src/report/season.ts`). 입춘이 지나면 같은 해의 ‘올해 운세’로 이어진다 |
| 구매 기록 | 로그인 없이 보이지 않는 계정 + 구매 코드(MG-XXXX-XXXX). 남기는 것은 ‘무엇을 · 어느 사주(암호값) · 얼마에 · 언제(신년운세는 그해)’뿐 |
| 지금 상태 | 베타라 모두 무료로 열려 있다(`BETA_FREE`). 실제 사이트에서는 잠금 화면·가격 버튼·결제 확인 창이 **나오지 않는다**(`?lock=1`도 개발 서버에서만). 잠금·결제 흐름·첫 결제 혜택은 시안(`PAYWALL_DEMO`)으로만 체험할 수 있고, 실제 결제 연동은 보류 중. 측정은 베타 동안에도 쌓인다(잠금이 없으니 ‘상세까지 봄’이 곧 관심도) |

**겹치지 않게 한 것**: 풀이 리포트의 연애·일·돈 탭에서는 10년 신호, ‘시기’ 카드, 이야기의 ‘시기’ 문단을 빼고 고민 리포트 상세에만 둔다(건강은 겁을 주고 파는 인상을 피하려고 무료 유지). 유료 상세에는 무료 탭의 카드·이야기를 다시 싣지 않는다. 운의 흐름은 이번 달·다음 달만 자세히 보여 주고, 나머지 달과 그해의 좋은 일·조심할 일 목록은 신년운세(올해 운세) 상세로 보낸다.

### 수익 구조

0. **첫 결제** — 고민 하나 1,900원(처음 한 번만). ‘처음 보는 사이트에 처음 돈을 내는’ 벽을 낮추는 장치이고, 본가격은 그대로 둔다
1. **상시** — 고민 상세 단건 3,900원
2. **대목** — 신년운세 6,900원. 10월~2월, 해마다 다시 팔린다 (매년 12~2월은 운세 이용이 느는 ‘신년 특수’)
3. **객단가** — 전부 열기 9,900원. 신년운세를 산 사람에게는 ‘3,000원만 더 내면 고민 4개까지’를 제안
4. **관계** — 궁합·재회 상대 한 명마다 4,900원
5. 하지 않는 것 — 광고(신뢰와 화면을 해친다), 구독(다시 올 장치가 아직 없다)
6. 나중에 — 오픈 특가(정말로 기간을 정할 때만 표시), 하반기 운세(7~8월), 인쇄용 PDF

결제를 붙일 때 할 일: 결제창(토스페이먼츠 등, 카카오페이·토스페이·네이버페이 같은 간편결제 포함) → 결제 확인 서버(예: Supabase Edge Function)가 구매 기록을 쓰고 → `src/lib/account.ts`의 `demoApi`를 같은 모양(`AccountApi`)의 실제 구현으로 바꾼다. 측정의 ‘결제 완료’도 그때 결제 확인 뒤로 옮긴다(지금 시안은 확인 창에서 바로 연다).
가격을 바꿀지는 결제를 붙인 뒤 측정으로 정한다 — 결제한 사람 수가 아니라 **접속한 사람 1명당 매출**(결제율 × 가격)로 비교한다.
지금은 유료 문장도 브라우저에서 만들어지므로 잠금은 화면을 가리는 수준이다. 정식 판매 전에 상세 부분을 서버에서 만들어 주는 방식을 검토한다(5절 참고).

## 3. 유료 전환 게이트 (서버 `stats().decision` 과 동일)

1. 리뷰 **100건 이상**
2. 평균 정확도 **3.8 / 5 이상** — 미달이면 과금보다 엔진 개선이 먼저
3. 지불 의향(무료만 제외) **25% 이상**
4. 유료로 묶을 섹션은 **평가 20건 이상 & 평균 4.0 이상**인 섹션만. 3.5 미만 섹션은 개선 대상

추가로 볼 지표: 신강약별·일간별·용신 확실성별 정확도 편차. 특정 구간이 낮으면 해당 판정 로직(`src/engine/strength.ts`)을 먼저 손본다.

## 4. 상품 구조 (가설 — 데이터로 확정)

| 등급 | 내용 | 가격 가설 |
| --- | --- | --- |
| **무료** | 정밀 만세력(원국·보정 내역·경계 민감도), 오행·십성, 신강약·용신, 대운 목록, 종합 요약, 성향 | 0원 — 정확도로 신뢰를 얻는 입구 |
| **상세 리포트 (1회)** | 연애·직업/이직·재물·건강 전체 + 10년 연도별 신호 + PDF | 4,900~9,900원 (지불 의향 중앙값으로 결정) |
| **월간 구독** | 매달 월운 상세, 이번 달 주의일, 연간 리포트 갱신 | 2,900~4,900원/월 |
| **단건 추가** | 궁합(두 명식 비교), 택일, 대운 10년 상세 | 각 4,900~14,900원 |
| **전문가 상담** | 리포트 기반 1:1 상담 연결(수수료 모델) | 상담가 책정 + 수수료 20~30% |
| **인생 웹툰 확장** | 기본 4컷·6컷은 무료(공유가 곧 홍보). 유료 후보: 고해상도·액자용 인쇄본, 주인공 외모 꾸미기, 궁합 웹툰(두 사람), 연간 운세 12컷, AI 일러스트 버전 | 1,900~4,900원 (웹툰 공감도 평가·공유 수로 판단) |

- 무료 영역을 너무 줄이지 않는다. 이 서비스의 차별점(계산 정확도·근거 공개)은 무료에서 체감되어야 유료 전환이 일어난다.
- 인생 웹툰은 **바이럴 입구**로 쓴다. 공유 이미지마다 사이트 주소가 찍히므로, 기본 웹툰은 무료로 두고 공유 수(`events`의 `share`)와 웹툰 공감도(섹션 `webtoon`)가 높게 나오면 확장판을 유료로 붙인다.
- 상세 리포트는 **“근거가 붙은 약점·리스크”**가 핵심 가치다. 미리보기로 각 섹션의 첫 블록과 한 줄 요약은 무료로 보여 주고, 나머지를 잠그는 방식을 우선 테스트한다.

## 5. 기술 적용 방법

1. `src/config/plans.ts`
   - `BETA_FREE = false`
   - `PREMIUM_SECTIONS` 에 잠글 섹션 지정 (`ReportView` 가 자동으로 잠금 표시)
2. 결제: 국내는 **토스페이먼츠** 또는 **포트원(PortOne)** 결제창 → 서버 웹훅에서 결제 검증 → 구매 토큰(서명된 JWT 등) 발급 → 클라이언트가 토큰을 보관하고 `/api/entitlement` 로 확인.
   - 리포트 생성은 지금처럼 클라이언트에서 해도 되지만, 유료 텍스트를 보호하려면 리포트 생성(`src/report/generate.ts`)을 서버 엔드포인트로 옮겨 **권한이 확인된 요청에만** 응답한다. 엔진은 순수 TS라 서버에서 그대로 import 가능.
3. 가격 A/B: `PRICE_OPTIONS`/상품 가격을 세션 해시로 분기해 노출하고 `events` 테이블에 `premium_interest` 이벤트로 기록 (이벤트 타입은 서버에 이미 허용됨).

## 6. 법·운영 체크리스트

- **전자상거래법**: 디지털 콘텐츠 청약철회 제한 사유를 결제 전 명확히 고지(열람 시작 시 철회 제한), 사업자 정보·통신판매업 신고 표시.
- **개인정보보호법**: 결제 도입 시 수집 항목이 늘어나므로 처리방침 개정. 생년월일시는 지금처럼 서버 미전송 원칙 유지가 가장 안전하다(유료 리포트를 서버에서 생성한다면 저장하지 않고 처리 후 폐기, 처리방침에 명시).
- **표시·광고**: “정확도 100%” 같은 표현 금지. “KASI 음력 자료와 일치 검증” 처럼 **검증 가능한 사실**만 쓴다.
- 건강·투자 관련 문장에는 현재처럼 “진단·투자 판단이 아님” 고지를 유지한다.
